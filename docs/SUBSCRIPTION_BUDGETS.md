# 账号模型价格与订阅周期额度

## 管理入口

- **账号管理 → 新建／编辑账号 → 模型价格**：新增模型，自动带入系统维护的官方价格，再按需修改。界面 token 单价单位为美元／百万 token。
- **订阅管理 → 套餐管理 → 新建／编辑套餐 → 周期额度**：设置每周期金额及重置规则，套餐有效天数独立控制订阅总有效期。
- **订阅管理 → 调整额度**：为存量订阅配置或修改额度。默认保留本周期已消费金额，勾选“清零当前周期消费”才恢复完整额度。单份及批量重置均支持新额度。
- 用户订阅页和订阅概览显示已用、余额和下次重置时间。

例如：套餐总有效期 30 天，每 6 小时恢复 10 美元。每周期剩余金额不结转；总有效期结束后停止使用，也不再发放新额度。

## 重置规则

- 每 N 小时：从订阅开通时刻起按固定 N 小时对齐，不随手动清零移动。
- 每天：指定时区的指定时刻。
- 每周：指定时区每周一的指定时刻。
- 每月：指定时区每月 1 日的指定时刻。
- 自定义天数：按开通日与指定时刻对齐，每 N 个日历日重置；首周期可能不足 N 天。
- 不重置：整个有效期只发放一次额度。

额度只在订阅总有效期内生效，最后一个周期可能不完整。

## 扣费与兼容

计费优先级为账号自定义价格、分组价格、渠道价格、系统官方价格库及现有兜底。账号匹配条目没有设置的价格字段使用官方价；删除全部账号价格条目则恢复原有定价链。分组倍率仍影响最终扣费。费用按实际使用量从订阅周期额度扣除，不会自动转扣用户钱包。

配置周期额度的订阅使用新额度，替代旧分组日／周／月金额限制；未配置的存量订阅保持旧行为。套餐修改只影响后续分配，已分配订阅及已创建订单保留额度快照。不同额度方案不能静默续接到同一活跃订阅，需要先明确调整现有订阅。

额度检查读取数据库权威用量，周期重置与扣费在同一条 SQL 中执行。额度耗尽拒绝后续请求并返回 HTTP 429。token 请求采用实际费用后结算，并发中的请求仍可能让最终消费略超额度；固定金额请求沿用现有预留机制。

## 部署与验证

部署新后端前备份数据库，启动时应用 `255_subscription_budget.sql`，同时部署匹配的前端。迁移不会自动给存量订阅发放新额度。

已验证前端类型检查、生产构建及相关组件测试；后端覆盖账号价格优先级、周期边界、到期、额度校验、修改与手动清零。临时 PostgreSQL 引擎验证了迁移、原子重置扣费、旧订阅兼容及 90 个 Go／SQL 周期边界一致性用例。仓库 Docker integration 测试需要本机可用 Docker 后再运行。
